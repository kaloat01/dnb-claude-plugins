# /article-apollo — dealership article, Apollo package

Input: `$ARGUMENTS` = dealer name + article title, e.g. `"Brickell Mazda" "Mazda CX-50 or CX-5: Which One Fits a Downtown Miami Garage?"`.
Engine command (use exactly, always quoted): **DA** = `node "${CLAUDE_PLUGIN_ROOT}/scripts/build.js"`
Knowledge (read when the phase says so): `${CLAUDE_PLUGIN_ROOT}/resources/rules/` → `rigor-and-content.md`, `compliance.md`,
`design-and-apollo.md`, `image-brief.md`; example of the quality bar: `${CLAUDE_PLUGIN_ROOT}/resources/examples/example-module.js`;
dealer data: `${CLAUDE_PLUGIN_ROOT}/resources/dealers/<key>.json` + `<key>.sitemap.txt` (a `./dealers/<key>.json` in the working folder overrides).

## Non-negotiable rules (keep these in mind for the whole run)
1. **Evidence before prose.** Every fact comes from the job's source ledger (primary sources: OEM, owner's manuals, government, statute). No ledger row → don't write it.
2. **Premise test first.** If the title's model year, number or claim isn't published by the OEM, stop and propose a corrected H1 (4 of the last 5 titles failed this).
3. **Never invent dealer facts:** no prices, ratings, awards, "certified/factory-trained technicians", urgency, guarantees, inventory or road-proximity claims. Attribute ("Our service page lists…") or turn into an ask.
4. **No dollar figures** except labeled, dated, model-year MSRP in comparisons (exclusions stated). "What it costs" → cost drivers.
5. **Independent review before the user sees the article:** compliance reviewer + golden-geo reviewer; fix every P0/P1. Writers never grade their own work.
6. **Design = Editorial v2, identical for every dealer.** Brand color on links only (+ logo). Never "01, 02" numbering. Don't restyle.
7. **Internal links only from the dealer's sitemap allow-list.** Dealer phones/hours only from the dealer file; items in its `verify[]` must be confirmed by the user before use.
8. **Images: general images, specific copy.** Vehicle photos must match the article's model year. View every photo before writing alt text.
9. Edit only the job's `module.js`; outputs are generated by DA — never hand-edit generated files.
10. Plain words with the user. Ask only questions whose answer changes the article (offer a recommended option).

## Phase 0 — Preflight (do immediately)
1. Run `DA env`. If Node is missing or < 18: stop and tell the user to run `/article-setup`.
2. Parse dealer + title from `$ARGUMENTS` (quoted values; an apostrophe in the title is fine). Run
   `DA new --dealer "<dealer>" --title "<title>"`. Exit 2 = ambiguous/unknown dealer → show the candidates and ask. If the job
   folder already exists, read its `job.json` and **resume at its `phase`** (don't restart).
3. Tell the user in 2 lines: dealer matched, job folder, what happens next. Read the dealer JSON and `rigor-and-content.md`.

## Phase 1 — Image request (first deliverable, non-blocking)
Read `image-brief.md`. Print the 5-slot image request (IMG_HERO, IMG_FIG1, IMG_FIG2, IMG_PAIR1, IMG_PAIR2) tailored to this
title: model + model year + angle + setting, min width, "no text/watermarks", rights note, and the Apollo upload + "send me
the Image ID or URL" steps. Write each slot's `desc` into `module.js`. Storefront + logo come from the dealer file.
Say: "Keep sourcing; I'll continue with research and drafting." Update `job.json` phase → `research`.

## Phase 2 — Intake (only what changes the article)
Infer article type (comparison · buying guide · service/maintenance guide · ownership/cost) and department (sales/service).
Defaults: no dealer prices; MSRP only in comparisons (labeled, dated, model-year, exclusions); cost topics → cost drivers.
Check the dealer sitemap for an existing page on the same topic (cannibalization) and mention it if found.

## Phase 3 — Research (ledger)
Spawn the agent **`dealer-articles:article-researcher`** (foreground) with: title, dealer file path, sitemap path, job folder,
today's date, article type, pricing policy, allowed local framing (`areas`, `climate`) and bans (`excluded`, `bans`).
It writes `<job>/<slug>-source-ledger.md`. Then:
- **Premise failed** → ⛔ AskUserQuestion: recommended corrected H1/scope first, keep-as-is second. Wait.
- Dealer `verify[]` items you will use (department phone/hours, routes) → ask the user to confirm them in one question.
Phase → `draft`.

## Phase 4 — Draft + build
Read `${CLAUDE_PLUGIN_ROOT}/resources/examples/example-module.js` (depth, voice, structure) and `rigor-and-content.md`
(anatomy, voice, banned words, claims discipline). Write `module.js` from the ledger only:
8–9 question H2s, each opened by an inline bold answer ≤25 words; body 1,700–2,300 words; 1–3 sourced tables; 1 callout with
verbatim OEM wording; 1 steps list; 1 stat strip; 1 inline CTA; hero + 2 full-width figures + 1 pair; local section with real
places/climate only; FAQ 9–10 × 40–90 words with new value; dealership section; 3 related cards from the allow-list; fine print.
Run `DA build "<job>"`. Fix every ❌ in `module.js` and rebuild until clean; address ⚠️ where sensible.

## Phase 5 — SEO + visual pass (always both skills)
1. Invoke the skill **`dealer-articles:golden-geo`** in **ARTICLE MODE** and apply its checks to the module (title ≤65, meta
   130–165, keyphrase in title/H1/dek/first bold answer, answer-first, FAQ ↔ schema, links). Rebuild.
2. Run `DA shot "<job>"` and Read the PNGs (1280 + 375). Invoke the skill **`frontend-design`** for a craft review of the
   screenshots **within the locked Editorial v2** (rhythm, hierarchy, alignment, crops, mobile). It must NOT change fonts,
   colors, layout or add brand styling. If `frontend-design` is not installed, use the design QA checklist in
   `design-and-apollo.md` and tell the user to run `/article-setup`. Apply module-level fixes; rebuild.
Phase → `review`.

## Phase 6 — Independent reviews (parallel, read-only)
In ONE message spawn **`dealer-articles:article-compliance-reviewer`** and **`dealer-articles:golden-geo-reviewer`**, each with
the paths to `module.js`, the preview, the ledger, the dealer file and the job context (article type, state, approved
deviations). Apply **all P0/P1** and sensible P2s (log skipped P2s with a reason in `job.json` notes). Rebuild → gates clean.
If a fix applies to a pattern, fix it everywhere in the article. Phase → `deliver`.

## Phase 7 — Deliver
Run `DA build "<job>"` (draft) or `DA build "<job>" --final` when every image has an Apollo ID (see `/article-images`).
Reply with:
- Preview: `<job>/<slug>-preview.html` (open in a browser). Package folder: `<job>/package/` (4 files + README).
- Word count, H2/FAQ counts, review verdicts (what was fixed), open `verify[]` items, legal flags (e.g. MSRP comparisons:
  dealer counsel sign-off where required).
- The SEO lines from `<slug>-SEO.md` exactly as written (`* Field  →  value`).
- Paste steps (short) and: "Site-wide CSS: paste once per dealer; re-paste only if the `dealer-articles css <hash>` comment
  differs from what is live."
- If images are still placeholders: "Upload the 5 images, then send me the Image IDs here or run `/article-images`."
If the user already sent image IDs/URLs in this session, follow `${CLAUDE_PLUGIN_ROOT}/skills/article-images/SKILL.md` now.
Phase → `images` (or `done` when final).

## Resume
Any time: `DA status "<job>"` shows the phase and outputs. Re-running `/article-apollo` with the same dealer + title resumes.
